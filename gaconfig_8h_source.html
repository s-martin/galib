13/* ----------------------------------------------------------------------------
14PREPROCESSOR DIRECTIVES
15
16 Here are the preprocessor directives that the library understands.
17
18 Some of these are already set up for the OSes with which I am familiar. See
19below for the pre-defined sets. If you come up with a compiler/platform
20configuration that is not listed here, please send it to me so that i can
21incorporate it into the code base.
22
23 GALIB_USE_PID
24
25 Define this if the system has a getpid function that
26 returns something sane and useful.
27
28 GALIB_USE_BORLAND_INST
29
30 For compilers that use the Borland instantiation model.
31 These compilers expect all of the template code to be
32 in the header file. The Cfront model, on the other
33 hand, expects source files with names similar to the
34 header files, but all of the template code does not
35 need to be in the header files.
36
37 When you define this flag, the source file that
38 corresponds to the header file is explicitly included
39 at the end of the header file for all headers that
40 contain templates.
41
42 GALIB_USE_AUTO_INST
43
44 For compilers that do not do automatic instantiation
45 (such as g++ version 2.6.8) you will have to force
46 instantiations. When this flag is not defined, GAlib
47 forces an instantiation of all of the template classes
48 that it uses (such as real genome and string genome).
49
50
51 GALIB_USE_RAN1 These specify which random number function to use. Only
52 GALIB_USE_RAN2 one of these may be specified. You may have to tweak
53 GALIB_USE_RAN3 random.h a bit as well (these functions are not defined
54 GALIB_USE_RAND the same way on each platform). For best results, use
55 GALIB_USE_RANDOM ran2 or ran3 (performance is slightly slower than most
56 GALIB_USE_RAND48 system RNGs, but you'll get better results).
57
58 If you want to use another random number generator you
59 must hack random.h directly (see the comments in that
60 file).
61
62 GALIB_BITBASE The built-in type to use for bit conversions. This
63 should be set to the type of the largest integer that
64 your system supports. If you have long long int then
65 use it. If you don't plan to use more than 16 or 32
66 bits to represent your binary-to-decimal mappings then
67 you can use something smaller (long int for example).
68 If you do not set this, GAlib will automatically use
69 the size of a long int. The bitbase determines the
70 maximum number of bits you can use to represent a
71 decimal number in the binary-to-decimal genomes.
72
73 GALIB_BITS_IN_WORD How many bits are in a word? For many systems, a word is
74 a char and is 8 bits long.
75
76---------------------------------------------------------------------------- */

132// ----------------------------------------------------------------------------
133// borland c++ compiler
134//
135// You may or may not need the BORLAND_INST flag defined when you use a borland
136// compiler. I did not need it when I compiled using version 4.0, but I did
137// need it when I compiled with an earlier version (I think it was 3.x but I
138// do not remember for certain).
139// Note that the default random number generator when using a borland (or
140// any PC compiler, for that matter) is the basic system's RNG.
141// I did this because of the hassles of 16- vs 32-bit DOS/Windows rubbish. If
142// you want a better RNG, you can use the others in GAlib, but you'll have to
143// do a bit of checking to make sure it works with your DOS/Windows config.
144// All of the RNGs work fine under all of the 32-bit OSes I've tried, but they
145// don't do so well in a 16-bit OS.
146// Use the randtest example to check GAlib's RNG after you compile everything.
147#if BOOST_COMP_BORLAND
148//#define GALIB_USE_RAND // comment this if you're using a 32-bit OS
149#define GALIB_USE_BORLAND_INST
150//#define GALIB_USE_PID

153//#pragma warning (disable : 8004) // unused variable warnings are lame

157#elif BOOST_COMP_MSVC
