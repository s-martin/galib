22-------------------------------------------------------------------------------
23Overview of who does what in the GAlibrary -- see http://lancet.mit.edu/ga/
24-------------------------------------------------------------------------------
25Here are the library capabilities and which parts of the library are involved:
26
27Genetic Algorithm
28 This object contains the operators and data needed to perform the
29 optimization. There are a few basic GA implementations in the library,
30 including the basic 'simple' genetic algorithm described by Goldberg, the
31 'steady-state' genetic algorithm, the 'incremental' genetic algorithm based
32 on the Genitor model, and the 'parallel' genetic algorithm that uses multiple
33 populations in parallel on a single CPU.
34 The base GA object defines many of the parameters and statistics useful
35 when running an experiment. It also defines the basic interface for most
36 genetic algorithms.
37
38Genome
39 The genome object contains the actual problem-specific data as well as the
40 mapping from data-domain to problem-domain (by way of the objective functions
41 All of the genomes are derived from a base genome class. The base genome
42 class defines the interface used by genetic algorithms to modify the data.
43 Any genome used in an experiment must be derived from the base genom class
44 as well as a user-defined data type (or one of the sample types provided in
45 GAlib). The library includes array, tree, list, and binary-string data types
46 to use if you do not want to define your own.
47
48Population
49 Each population contains a bunch of genomes. Populations know how to
50 select genomes. They also have housekeeping routines such as replace,
51 remove, and add. A population can be given some intelligence by using its
52 evaluation member rather than evaluting each individual on its own.
53
54Selection
55 Selection is implemented as a member function of the population object.
56 Any GA simply calls the population's 'select' member to get the genome that
57 it needs to work with.
58
59Crossover/Mating
60 Crossover is implemented as a separate object. We have various crossover
61 objects, each corresponding to a genome type. These could be templatized,
62 but that wouldn't buy us much since the behaviour depends upon the data type
63 anyway.
64 Crossover is not a member function of the genomes. I fretted over how to
65 do this properly and decided to keep crossover as an operator separate from
66 the genomes. The other viable option was to make crossover a member function
67 of the genomes, but then changing the crossover during the course of the
68 evolution becomes more difficult. Also, it is easier to define asexual (or
69 other non-standard mating schemes) with an operator that is not a member of
70 the genome object.
71 When you create a GA, you specify a genome (or population of genomes). The
72 GA asks the genome how it mates, and the genome returns a pointer to its
73 preferred crossover method. You can set the crossover explicitly on the GA
74 if you prefer. Using this scheme we can assign default crossover operators
75 so that you don't have to specify a crossover unless you want to.
76 Each genome type must have a corresponding crossover operator defined that
77 can operate on that data type. The genetic algorithms don't care about the
78 specific crossover type - they call the mating methods based upon the high
79 level interface definition.
80
81Mutation
82 Mutation is defined at the genome level and is implemented as a member
83 function of the base genome class. Each genome must define its own
84 mutation method that will operate on its specific data type.
85
86Replacement strategies
87 The replacement strategy defines how a child is inserted into a population.
88 Replacement strategies include child-replaces-parent, child-replaces-worst,
89 and child-replaces-random. These make sense only for GAs with overlapping
90 populations.
91
92Convergence and completion
93 The GA defines a 'done' member that calls a user-defineable completion
94 function to determine whether or not the GA is finished. Built-in completion
95 routines include population-converged, best-converged and
96 number-of-generations.
97
98Fitness vs Objective
99 Note the difference between fitness function and objective
100 function. In this library, the objective function is user-defined and tells
101 (on an arbitrary scale) how well a genome performs relative to other
102 genomes. The fitness function, on the other hand, takes objective function
103 scores and processes them to produce a number for each genome that
104 represents its fitness for mating/selection.
105 The selection strategies include roulette wheel, tournament, linear
106 ranking, and stochastic sampling. See the selector headers for more details
107 about each strategy and its implementation.
108 Speciation is included as a type of selection. To use the speciating
109 selector you must define a distance function. See the selector header for
110 more details.
111 Scaling methods are loosely coupled with the selection strategies. They
112 include linear scaling, sigma truncation, and ranking. See the fitness
113 headers for more details about how you can mix and match scaling methods with
114 selection strategies.
115
116Elitism
117 Elitism is optional. If you want the best of each generation to be carried
118 over to the next generation, turn on the elitism. If not, turn it off. This
119 only works with non-overlapping populations.
120
121Initialization
122 Each genome has its own initialization operator. When a GA is
123 initialized, it initializes its populations, which in turn tells each
124 chromomosome to initialize itself. You can use the initialization method to
125 bias an initial population. This can be done either at the population level
126 by customizing the population's initialization operator or at the genome
127 level by customizing the genome's initilizer.
128 Default initializers are included for most genomes. See the documentation
129 and genome headers for more details.
130
131-------------------------------------------------------------------------------
132Basic usage
133
134 You create a GA by first instantiating the non-default parts that you want to
135use. For example, if you want a binary string genome with uniform crossover
136and roulette wheel selection, you would define an objective function,
137instantiate a genome, instantiate a uniform crossover operator, then
138instantiate the GA. Since the roulette wheel selector is the default, you do
139not need to instantiate one to use that method.
140 In every case you MUST define an objective function and you MUST instantiate
141one copy of the genome type you want to use.
142
